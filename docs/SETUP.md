# 安装排查

## Mac 应用（v0.7）

- **打不开 / 提示无法验证开发者**：系统设置 → 隐私与安全性 → 在下方点“仍要打开”。这是未使用 Apple 开发者证书签名造成的，只需一次。
- **一直停在“等待 Docker 就绪”**：看看 Docker Desktop 窗口是否在等你同意条款或完成首次设置；完成后工作台会自动继续。等待超过 10 分钟会提示重试。
- **“载入浏览器组件”失败**：多半是磁盘空间不足或 Docker 磁盘已满（镜像约 1.8 GB）。详情在数据文件夹的 `build.log`；应用会尝试改为联网构建。
- **提示“另一个境工作台正在使用同一个数据文件夹”**：通常是还开着磁盘映像（DMG）里的那一份，退出它、推出磁盘映像后点重试。
- **窗口里显示“工作台没有启动”**：点“查看日志”打开 `~/Library/Logs/BrowserWorkbench/backend.log`；点“重试”重新启动后台服务，浏览器环境不受影响。
- **旧版（源码 / 网页版）和应用可以同时开**：两者数据目录、端口、容器名都不同，互不影响；但它们看到的是两份独立的数据。

以下为源码运行（网页版）的排查。

## Python 版本不够

需要 Python 3.11+。在终端执行 `python3 --version` 检查。若装了多个版本，可先用 `python3.11 launch.py` 等明确版本命令启动。

## Docker 尚未就绪

v0.6.1 起，工作台会自动打开已安装的 Docker Desktop、等待引擎就绪，再自动准备浏览器组件。也可在“运行组件”点击“一键准备”。如果 Docker 有首次启动条款或系统提示，请在其窗口完成；工作台会继续等待。等待超时后可重试，无需手动创建容器。

macOS 已安装但命令不在 PATH 时，工作台也会检查标准的 Docker 应用路径。

## 镜像准备失败

检查网络是否能访问 Docker Hub、Debian、PyPI 和 GitHub release。不要关闭证书验证。详情在自己的 `data/build.log`；分享日志前先检查其中的个人目录与网页内容。

Dockerfile 默认从 Debian 软件源安装 Firefox ESR，因此实际小版本会随软件源更新。不是所有构建日期都得到同一个浏览器版本。

## 提示资源不足

电脑物理内存和 Docker Desktop 分配内存是两个值。工作台按 Docker 可用容量限制环境的内存额度合计，并预留512MB。可以降低环境额度或停止不用的环境；调整 Docker Desktop 容量应按自己的电脑情况进行。

## 启动后网页不显示

本机地址默认是 http://127.0.0.1:8766。该端口被其他应用占用时，双击入口会提示冲突。可用 `python3 run.py --port 8768` 启动其他端口，但双击入口仍只管理默认端口。

## 更新源码

保留自己原来的 `data/`。替换源码并重启面板；重新构建镜像后，正常停止并重新打开环境才加载新组件。不要运行会删除绑定 profile 的清理命令。

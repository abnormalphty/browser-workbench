# 数据与分享说明

## 什么保存在本机

Mac 应用的数据在 `~/Library/Application Support/BrowserWorkbench`，日志在 `~/Library/Logs/BrowserWorkbench`；源码运行时在项目的 `data/`。

注意：macOS 开启“桌面与文稿文件夹”iCloud 同步时，放在“文稿”或“桌面”里的项目 `data/`（含订阅和浏览器登录数据）会被上传到 iCloud。应用的数据目录不在同步范围内。

`data/` 中包含 SQLite 元数据、订阅地址、节点连接参数、浏览器 profile、账号备注、日志以及上传 / 下载文件。该目录不属于源码分享内容。登录文件沿用 Firefox 自身的存储方式，不承诺天然加密；请按个人数据保管。

账号核对仅在点击后打开临时 Claude 账单窗口，不读取登录数据库，也不返回对话正文。它会读取 X11 PRIMARY 文字选区，不改写环境的 CLIPBOARD。

## 会访问哪些外部服务

- 导入 / 更新订阅时，访问使用者填写的订阅服务。
- 启动正式环境时，通过所选代理访问 api.ipify.org 查询出口 IP；出口地理检测（导入订阅后和每次打开工作台时自动进行）通过被检测的线路访问 ipwho.is，无响应时改用 ipinfo.io。
- 浏览器访问使用者打开的网站；账号核对打开 Claude 设置页。
- 源码运行或联网构建时访问 Python、Debian、Docker 和 GitHub 等软件源；Mac 应用默认载入自带的浏览器组件，不需要这些访问。
- 应用里点“下载 Docker Desktop”时，用默认浏览器打开 Docker 官方下载地址。

不设置独立的项目遥测或账号收集服务。网站、代理提供商以及上游软件本身的数据政策各自适用。

## 分享前检查

1. 分享源码仓库，避免直接打包已运行的项目目录。
2. 不上传 `data/`、浏览器 profile、Cookie / 登录数据库、订阅地址、代理配置、账号备注、传输文件、日志和截图。
3. `.gitignore` 只能阻止未跟踪文件；已提交过的数据仍可能留在 Git 历史中。不要依靠删除最新版本来清除历史秘密。
4. 本分享版本从源码白名单新建目录，无旧 Git 历史，不含原工作台的运行数据、截图或聊天记录。
5. 当前仓库为公开仓库，任何人都可查看和下载源码。后续提交也应继续排除个人运行数据。
6. Mac 应用由构建脚本按白名单组装，并在签名前运行 `scripts/check_bundle.py`：应用包里出现数据库、日志、浏览器配置、私钥或构建者本机路径时，构建直接失败。随附的浏览器组件镜像只由 `runtime/` 里的文件构建。

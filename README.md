# Browser Workbench · 本地浏览器工作台

在自己的电脑上管理独立的 Firefox 浏览器环境。导入代理订阅、选择线路、打开浏览器，分别保存各环境的登录数据。

这是不含预设账号与个人数据的源码分享版。首次启动为空工作台，订阅与网站账号由使用者自行提供。

## Mac 应用（v0.7 起，推荐）

从 [v1.1.0 发布页](https://github.com/abnormalphty/browser-workbench/releases/tag/v1.1.0) 下载 `Browser-Workbench-1.1.0-arm64.dmg`（Apple 芯片），打开后把“Browser Workbench”拖进“应用程序”，双击即可在独立窗口中使用，不需要安装 Python、打开终端或浏览器。

从 0.7 或 1.0 版升级时，直接替换“应用程序”里的旧版即可：环境、登录数据和订阅都会保留（以前的环境都算作 Claude 环境），第一次打开时会自动载入一次新的浏览器组件。

- **首次打开被 macOS 拦截**：当前版本没有 Apple 开发者证书签名。到“系统设置 → 隐私与安全性”，在下方点“仍要打开”，只需一次。
- **Docker**：浏览器环境仍运行在 Docker 里。应用会自动找到并打开 Docker Desktop（或 OrbStack），然后载入 DMG 自带的浏览器组件，不需要联网构建，也不需要设置 Docker 的代理或镜像源。还没有安装 Docker Desktop 时，应用会给出对应芯片的官方下载链接和步骤。
- **数据**：保存在 `~/Library/Application Support/BrowserWorkbench`，日志在 `~/Library/Logs/BrowserWorkbench`。用过下面的网页版时，可在菜单“文件 → 导入旧版工作台数据…”选择旧目录里的 `data` 文件夹：只复制，不改动旧数据。
- **关闭与退出**：关窗口不会停止环境（点 Dock 图标重新打开）；⌘Q 时如有环境在运行，会询问是否一起停止。

应用内“从电脑粘贴”“复制到电脑”直接使用系统剪贴板，不再出现浏览器权限提示；“下载到电脑”保存到“下载”文件夹；可以把 Finder 里的文件直接拖到环境画面上传入。结构、取舍与构建方法见 [Mac 应用说明](docs/DESKTOP.md) 和 [构建 DMG](docs/BUILD.md)。

Intel Mac 版本尚未构建和验证。

## Windows 版（v0.8 起）

从 [v0.8.1 发布页](https://github.com/abnormalphty/browser-workbench/releases/tag/v0.8.1) 下载 `Browser-Workbench-0.8.1-x64-Setup.exe`，双击安装（只为当前用户安装，不需要管理员权限），从开始菜单或桌面打开。适用于 64 位 Windows 10（22H2）和 Windows 11。

Windows 版还是 0.8.1：1.0 起的环境切换条、全屏、终端、模型网关，以及 1.1 的其他 AI 网站和模型，Windows 版稍后更新。

- **选择位置**：安装时可以选程序装在哪里；第一次安装时还可以选数据放在哪里（例如 D 盘）。由工作台替你安装 Docker Desktop 时，浏览器组件和各环境的登录状态也会放到数据旁边。

- **首次运行被拦截**：安装包没有代码签名证书，Windows 可能提示“Windows 已保护你的电脑”，点“更多信息 → 仍要运行”。打开了“智能应用控制”的电脑会直接拦下未签名程序。
- **Docker**：需要 Docker Desktop（使用 WSL 2、Linux 容器）。没有安装时，点“同意并自动安装”，应用会完成全部准备：
  - 从 Docker 官网下载安装包，核对 Docker 的数字签名；
  - 只为当前用户安装 Docker Desktop，不需要管理员权限；
  - 启动 Docker Desktop，并载入安装包自带的浏览器组件。

  如果电脑还没开启 WSL 2，Windows 会请你授权一次，之后需要重启一次；重启后应用会自动打开并继续。也可以手动安装，装好后应用同样会自动继续。Docker Desktop 处于“Windows 容器”模式时，应用会自动切回 Linux 容器。
- **数据**：数据库、订阅和文件传输文件夹默认在 `%LOCALAPPDATA%\BrowserWorkbench\Data`（或安装时选的位置）；各环境的 Firefox 登录数据放在 Docker 存储卷里（原因见说明）。“账号与资源 → 存储位置”列出每一处的位置和大小，也可以把数据移到别处。卸载应用不会删除这些数据。
- **关闭**：关窗口即退出；有环境在运行时会询问是否一起停止。

结构、数据位置与构建方法见 [Windows 版说明](docs/WINDOWS.md)。Windows 版已在 Mac 上完成构建和模拟验证，也在 GitHub 提供的 Windows 机器上跑过安装与自检，但还没有在装了 Docker Desktop 的真实 Windows 电脑上验收。

## 从源码运行（网页版）

以下是 v0.6 起的源码运行方式，适合开发或不使用 DMG 的情况。

### 需要准备

- macOS，Python 3.11 或更新版本。
- 已安装的 [Docker Desktop](https://www.docker.com/products/docker-desktop/)。
- 首次安装能访问 Python 软件源、Debian 软件源、Docker 镜像源及 GitHub 发布文件的网络。
- 足够的磁盘空间和 Docker 内存；浏览器镜像为数 GB，默认每个环境最多 2 核 / 2 GB，同时运行上限为 2。

已在 Apple Silicon Mac 验证主要功能。Dockerfile 同时按构建平台选择 ARM64 / AMD64 组件，但 Intel Mac 尚未实际验收。Windows / Linux 主机尚未完成支持，不能把浏览器容器使用 Linux 理解为这些主机可直接双击运行。

### 下载和启动

仓库已按拥有者选择公开发布，可以直接下载源码。

1. 点击仓库 **Code → Download ZIP**，解压到自己常用的目录。
2. 安装 Python 3.11+ 和 Docker Desktop。工作台会自动打开 Docker 并等待就绪；Docker 的首次启动提示仍需在其窗口完成。
3. 双击目录内的 **启动工作台.command**。也可在这个目录的终端执行 `python3 launch.py`。
4. 首次启动会在项目目录建立 `.venv`、安装依赖，自动等待 Docker 就绪并准备浏览器镜像。页面会显示当前阶段，失败后可点“一键准备”重试；首次准备可能需要数分钟。
5. 日后仍从同一目录启动；面板地址为 [http://127.0.0.1:8766](http://127.0.0.1:8766)。

如果双击文件没有运行权限，可在该目录执行 `chmod +x 启动工作台.command`，或直接运行 `python3 launch.py`。如系统提示 Python 版本过低，请安装新版 Python 后再启动。

## 开始使用

1. 在“订阅与线路”粘贴自己的通用或 Clash 订阅地址并导入。支持常见 SS、VMess、VLESS、Trojan、Hysteria2；不是所有 Shadowrocket 扩展格式都可用。
2. 创建环境，选择要打开的网站（Claude、ChatGPT、Gemini、Grok、Perplexity、Microsoft Copilot、DeepSeek、Kimi、豆包、千问，或填写其他网站的 https 地址），再选择节点。没有订阅时，可以明确选择“无代理测试模式”。一个环境建议只登录一个账号。
3. 点击“打开浏览器”，在网页内操作 Firefox，并自行登录网站。
4. 返回工作台不会停止环境；点击“停止”释放资源，登录数据继续保留。

普通标准 Firefox 不提供伪装设备或保证网站登录成功的能力。本工具不提供 Claude、ChatGPT 等网站的账号、订阅或额外使用额度，也不是任何付费教程的原始软件。

## 复制和文件传输

- 主电脑到环境：先点中环境内输入框，再按 ⌘V，或使用“从电脑粘贴”“中文输入 / 粘贴”。支持文字及 PNG 剪贴板图片。
- 环境到主电脑：选中文字后按 ⌘C，或点击“复制到电脑”。主电脑浏览器若拒绝写入剪贴板，会提供选中文字的备用窗口。
- 电脑文件传入：打开“文件传输”，选择或拖入文件；在远程网页的文件选择框中打开“电脑传入文件”。
- 下载到电脑：先在网站点击实际下载；完成后在“文件传输 → 环境下载文件”取回，或在 Finder 中打开。
- 拖入文件（v0.7）：把文件从 Finder 拖到环境画面上即可传入；单张 PNG 会直接粘贴进网页。

单次粘贴文字最多 20000 字符，PNG 最多 20 MB，文件上传最多 100 MB，复制取回文字最多 2 MB。Claude 回复里只有 `/home/claude/...` 这样的文字路径时，文件仍可能在其云端执行环境；需要先让网站提供真正可下载的附件。

## 环境切换、全屏和终端

- 打开环境后，画面上方的切换条列出全部环境和各自的状态，点一下就切过去：已启动的直接打开，低功耗的先唤醒，未启动的先启动，还没绑定线路的会请你先选线路。
- 右上角的“全屏”让环境画面占满屏幕，按 Esc 或“退出全屏”返回。
- “终端”标签在环境里打开命令行（环境内的 browser 用户，bash）。正式环境里的命令和浏览器一样经过这个环境的线路；测试模式直接连接。停止环境后只保留 `/profile` 里的文件，放进 `/profile/transfer/downloads` 的文件可以在“文件传输”里取回。每个环境最多同时开 4 个终端；关掉页面或停止环境，终端里的程序随之结束。

## 全球节点地图和时区

地图先按节点名称推测地区，然后自动检测每条线路的实际出口：导入或更新订阅后、每次打开工作台时，在后台逐条通过线路查询出口所在城市，结果标在地图上（附近有中文名的城市显示中文名）。已检测的线路一周后会重新检测；检测失败的 12 小时后再试；“重新检测出口”会立即检测全部线路。也可以手动选择城市，手动设置不会被检测结果覆盖。名称推测、出口检测、手动指定会分别标明；“剩余流量 / 到期时间”这类订阅信息条目不检测。

绑定线路的环境每次启动时按线路所在城市的 IANA 时区运行，夏令时和冬令时由时区规则自动切换（运行中跨过换季时刻也会切换）。线路卡片和环境设置里会显示冬令时、夏令时各是 UTC 几点，以及现在处于哪一段。城市还没确定时，启动前会先检测出口；检测不到时，新环境会提示先选择城市，旧版创建的环境照旧以 UTC 启动。出口检测通过被检测的线路访问 ipwho.is，无响应时改用 ipinfo.io，不会把订阅地址交给第三方转换站。

## 账号与资源

“账号与资源”页显示环境 CPU / 内存、使用额度及账号记录。

- 每个环境的“账号信息”按它的网站列出套餐（例如 ChatGPT 的 Free / Go / Plus / Pro，Gemini 的 Google AI Pro / Ultra），可以手动记录套餐和状态。改了环境的网站后，登录数据保留，记录的套餐和状态清空，需要重新记录。
- Claude 环境登录后，还可以点击“账号信息 → 核对当前账号”。它会短暂打开账单窗口，读取明确的当前套餐或停用提示，然后返回原窗口。核对期间请暂不操作环境内浏览器。其他网站暂不支持自动核对。
- Free / Pro / Max 等仅在找到明确证据时更新；普通网络或登录失败不会当作封禁。无法识别时保留历史记录，也可以手动标记。邮箱与账号备注由使用者手动填写，来源会标明。
- “低功耗”暂停本地环境，“唤醒”继续。暂停保留内存和运行名额；Claude 云端任务可能继续。停止环境才释放内存。
- “运行设置”可设 1—100 个同时启动名额，实际并发受运行组件容量限制；启动中、运行中、暂停均计入。
- 每个环境可修改 CPU 与内存额度，正在运行时即时生效。内存上限合计要为 Docker 保留 512 MB；暂停环境不能直接缩减内存，运行中用量过高也会拒绝不安全的缩减。

## 模型网关

让这台电脑上的其他程序（Cherry Studio、Claude Code 等）通过一个本机地址使用 Claude、GPT、Gemini、DeepSeek 等模型，用的是你自己的 API 密钥：

1. 在各家的控制台创建 API 密钥（按实际用量计费），在“模型网关 → 添加 API 密钥”里选择服务后保存。可选的服务：Anthropic（Claude）、OpenAI（GPT）、Google Gemini、DeepSeek、xAI（Grok）、Moonshot（Kimi）、阿里云百炼（通义千问）、火山方舟（豆包）、智谱 BigModel（GLM）、OpenRouter，以及“其他兼容服务”（填写接口地址，OpenAI 兼容或 Anthropic 兼容；这台电脑上的 Ollama、LM Studio 等可以用 http 地址，也可以不填密钥）。保存前会读取一次模型列表来验证；服务没有列出的模型（例如火山方舟的接入点 ID）可以在“手动添加的模型”里填写。
2. 为每个要接入的程序“新建专属密钥”：可以指定用哪个 API 密钥，或选“自动”，让每个请求交给提供所选模型的 API 密钥（几家的模型都能用，默认 API 密钥优先）；还可以限制允许的模型（或固定用一个模型）。程序只拿到专属密钥，拿不到 API 密钥；可以随时停用、更换或删除。
3. 开启网关，按“接入方法”把地址和专属密钥填进程序：OpenAI 兼容格式填 `http://127.0.0.1:18766/v1`，所有添加了密钥的模型都能用；Anthropic 格式填 `http://127.0.0.1:18766`，只能用 Claude 模型（以及 Anthropic 兼容的服务）。Claude Code 可以用接入方法里给出的一行命令启动，它只能用 Claude 模型。

- 网关只监听 127.0.0.1，只有这台电脑上的程序能连接；工作台开着时它才运行。端口和连接各家 API 用的代理在“网关设置”里修改：留空代理时按系统设置，填写后只用填写的代理；这台电脑和局域网里的服务不走代理。
- Claude 的请求经官方 SDK 原样转给 api.anthropic.com，流式输出、工具调用、`anthropic-beta` 等照常可用；OpenAI 格式的请求发给 Claude 模型时会换成 Claude 的格式，temperature 等 Claude 不接受的参数会被忽略。其他服务的请求按 OpenAI 格式原样转发，只换上模型和 API 密钥。程序中途断开时，网关同时结束对上游服务的请求。
- 每个专属密钥显示今天和近 30 天的请求次数与 token 数，只供参考，费用以各家控制台为准。
- “设置历史”记录每次修改，可以回到任何一步；API 密钥本身（名称和手动添加的模型除外）、还在使用的专属密钥和网关开关不会被换回旧的。
- Claude Pro / Max、ChatGPT Plus 等网页订阅的登录不是 API 密钥，不能用于网关，网关也会拒绝网页登录用的令牌；工作台不会读取环境里网页的登录状态。

## 数据和分享

源码运行时，所有本机数据位于 `data/`；Mac 应用则在 `~/Library/Application Support/BrowserWorkbench`。其中包括订阅、节点密钥、浏览器登录数据、账号备注、传输文件，以及模型网关的 API 密钥和专属密钥。普通停止会保留；删除环境会清除该环境数据。如果项目放在由 iCloud 同步的“文稿”或“桌面”里，`data/` 也会被上传到 iCloud。

仓库默认排除 `data/`、`.venv/`、日志、数据库、测试输出。分享源码时不要把自己的整个运行目录压缩上传。详见 [数据与分享说明](docs/PRIVACY.md)。

本机面板和浏览器端口只监听回环地址；这是单人本机工具，没有多人服务端的权限设计，不适合直接公开到互联网。WebRTC 默认关闭，以避免绕过所选代理，因此网页语音 / 视频功能可能受影响。

## 开发和验证

```sh
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
.venv/bin/python -m unittest discover -s tests -v
```

实际容器集成验证（需要 Docker，会创建并清理独立测试环境，不使用个人订阅或账号）：

```sh
.venv/bin/python tests/integration_runtime.py
.venv/bin/python tests/integration_transfers.py
```

测试前需要在“运行组件”中准备镜像，或执行：

```sh
docker build -t local-browser-workbench:0.7.0 runtime
```

项目结构及验证范围见 [架构说明](docs/ARCHITECTURE.md) 和 [验证说明](docs/TESTING.md)。常见问题见 [安装排查](docs/SETUP.md)。第三方项目及许可边界见 [第三方说明](THIRD_PARTY_NOTICES.md)。


## v0.6.1 首次准备改进

Docker 已安装时，工作台把“启动 Docker → 等待就绪 → 准备浏览器组件”串成一次操作；已有组件会直接复用。Docker 未就绪时不再立即构建失败。页面显示正在等待还是正在准备，超时后可重试。首次启动 Docker 的条款或系统确认仍需使用者自行完成。

## v1.0.0 环境切换、全屏、终端和模型网关

这一版只发布 Mac 版（Apple 芯片）；Windows 版稍后更新，目前仍是 v0.8.1。

- 环境切换条：打开环境后，画面上方列出全部环境和各自的状态，点一下就切过去。
- 全屏：环境画面占满整个屏幕，按 Esc 或“退出全屏”返回。
- 终端：在环境里打开命令行（环境内的 browser 用户），每个环境最多同时开 4 个。
- 模型网关：用自己的 Anthropic API 密钥，让这台电脑上的其他程序（Cherry Studio、Claude Code 等）通过一个本机地址使用 Claude。每个程序一把专属密钥，可以限制模型、查看用量、随时停用；支持 Anthropic 和 OpenAI 两种格式；设置历史可以回到任何一步。按 API 的实际用量计费，Claude Pro / Max 订阅不能通过网关使用。
- Mac 版的浏览器组件升到 0.8.0（与 Windows 版相同）：从 0.7 版升级后第一次打开时会自动载入一次，环境和登录数据不变。

## v0.8.1 Windows 版：选择安装和数据位置

- 安装向导可以选择程序的安装位置；第一次安装时还可以选择数据的存放位置。已有数据时不会改动它。
- 新增“账号与资源 → 存储位置”：列出程序、数据、Docker 数据的位置，每个环境的登录状态和传输文件各占多少空间。
- 可以把数据移到其他文件夹或磁盘：先停止环境，复制后逐个文件核对，全部一致才改用新位置；原来的文件夹保留为“旧数据”，确认后可以在应用里删除。各环境的登录状态不受影响。
- 由工作台安装 Docker Desktop 时，它的 Linux 磁盘（浏览器组件与登录状态）放在数据旁边；已经装好的 Docker Desktop，说明如何在它的设置里移动。安装前按各个磁盘分别检查剩余空间。
- 修复：开启 WSL 2 之后还没重启时，Windows 可能已报告“虚拟机平台已开启”，工作台随即开始安装，Docker Desktop 却提示 “Virtual Machine Platform is not enabled”。现在会核对开机时间、Windows 是否在等待重启、虚拟机监控程序是否在运行，需要时先请你重启。
- 修复：已经装好的 Docker Desktop 因为同样的原因启动不了时，工作台也会检查电脑并给出步骤（开启 WSL 2、重启，或修复被其他软件关掉的虚拟化），不再只是等待。
- Mac 版不变，仍是 v0.7.3。

## v0.8.0 Windows 版

- 新增 Windows 版：WebView2 窗口、自带 Python 与 x64 浏览器组件、只为当前用户安装的安装程序（NSIS），可在 Mac 上构建。界面、后端与 Mac 版共用。
- Windows 上各环境的 Firefox 登录数据放在 Docker 存储卷，文件传输文件夹仍在 Windows 数据目录；后台调用 Docker 时不再闪出命令行窗口。
- 浏览器组件升级到 0.8.0：从 Windows 共享进容器的文件夹不能改所有者时，容器照常启动。Mac 版 0.8.0 发布后，第一次打开时会自动载入一次新组件。
- 网页界面按系统显示说法（资源管理器 / Finder、Ctrl+V / ⌘V）和 Docker Desktop 的安装步骤。
- Windows 上可以一键安装 Docker Desktop：
  - 从 Docker 官网下载，断线后能续传，并核对 Docker 的数字签名；
  - 只为当前用户安装，不需要管理员权限；
  - 需要时请 Windows 授权一次开启 WSL 2，并在重启后自动继续。
- Windows 上能找到只为当前用户安装的 Docker Desktop（Docker Desktop 4.83 起的默认安装方式）；Docker Desktop 处于“Windows 容器”模式时会自动切回 Linux 容器。
- 浏览器组件的构建在网络不稳定时会重试下载并保留已下载的软件包。

## v0.7.3 自动检测线路位置

- 导入或更新订阅后、每次打开工作台时，在后台自动检测每条线路的实际出口城市并标到地图上，不用再手动点按钮，也不再只检测前 100 条；附近有中文名的城市显示中文名。出口检测在 ipwho.is 无响应时改用 ipinfo.io。
- 所有绑定线路的环境（包括旧版创建的）启动时都按线路所在城市的时区运行，夏令时 / 冬令时自动切换；线路卡片和环境设置里显示冬令时、夏令时各是 UTC 几点，以及现在处于哪一段。
- 修复：节点名称里的简体“东京”认不出来；新增“大阪”。

## v0.7.2 修复订阅导入

- 修复：机场的 Clash 订阅带有大量分流规则时，导入提示“订阅超过 2 MB”并停止。上限放宽到 32 MB；导入时只读取其中的节点部分，不再解析规则，大订阅也能很快导完。
- 订阅里个别节点用了暂不支持的协议或设置时，跳过这些节点并提示数量，其余节点照常导入（以前会整份订阅导入失败）。

## v0.7.1 修复窗口拖动

- 浏览器组件仍是 0.7.0：已经载入过的不需要重新载入。
